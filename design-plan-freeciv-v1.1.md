> **[AMENDMENT 2026-10-24 — decision 8 (run manifest), fingerprint probe redesign.]** Deterministic single-sample greedy decoding required `top_p=1.0`, which is now forbidden (see the 2026-10-24 amendment to decision 4). The per-arm fingerprint probe is therefore a K=3 multi-sample probe run under the arm's own sampling (temperature 1.0, `reasoning_effort="high"`, no `top_p`). The reference is itself a K=3 sample set re-established under the new sampling; match = non-empty intersection of the reference sample set and the arm's sample set. This is documented explicitly as a canary rule, NOT an equivalence relation. Drift policy wording carried over: between-arm mismatch -> one re-probe -> persistent mismatch -> drift-suspect. A probe-prompt v2 is required: the v1 probe prompt is a verbatim echo task that degenerates the K-sample canary; v2 must be capacity-revealing (outputs varying across models yet comparable across runs).

## 2. Research register (deep round 2026-10-24; factual claims verified live against primary sources during review)

- **taso-labs/freeciv-llm + CivBench Season #001** (github.com/taso-labs/freeciv-llm, AGPL-3.0; tasolabs.com blog): 8 models, ~200-turn games, Feb 2026; usable matches $7.15–$37.94, Claude Opus 4.6 $987.95; winner MiniMax M2.5 $11.57/match; **reason-but-don't-act** was the largest fault (GPT-5.2: 75.8% = 403/532 threat mentions with no action within ±2 turns) — instrumented from day 1 here.
- **chonk-doom** (github.com/goums/chonk-doom, `docs/CHALLENGE.md`): ~5.5k input tokens/turn, input ≈87% of cost; fixes = stable prefix caching, lean history (last turn full, older one-liners), one batched `act` call, interrupts on salient events; "bloopers" fixed by harness changes (exact coordinates in text), not model changes; video early — community voting is up-arrow driven.
- **SAGA** (arXiv 2606.29932): LLMs cannot infer spatial relations from raw coordinates — observations carry exact coordinates AND relative direction/distance statements with precomputed semantics.
- **Age of LLM** (arXiv 2606.24391): 58% of illegal actions were fog/state errors (verbatim from the abstract) → illegal-action taxonomy drives class-specific remedies; replay format + static viewer as first-class artifacts.
- **CivBench paper** (arXiv 2609.02459, civ6): PMR and RAG@10 (commitments executed within 10 turns: 48.2%–65.8% across models) — both log-derived; the RAG@10 idea is adopted here as commitment follow-through with a frozen commitment grammar (the PMR idea is NOT adopted: our pipeline has no proactive query interface, so "queries within window" would measure the harness, not the model).
- **Vox Deorum** (arXiv 2512.18564): LLM macro + algorithmic tactical hybrid across 2,327 games — validates enumerate-then-choose.
- **nace-ai/civ6-mcp Drex mode**: a decisions-only scripted controller completes turns with no generative model → our scripted comparator doubles as the degraded-default engine; built first.
- **TextStarCraft II CoS** (arXiv 2312.11865): two-tier observation (compact snapshot + delta report) is the standard token-budget answer.
- **Factorio LE** (arXiv 2503.09617): GPT-4o repeated one invalid operation 78 contiguous steps — bounded repair (cap 2) is mandatory.
- **CivWorldBench** (arXiv 2610.16450, Freeciv engine): belief inference is measurably separable — supports fog-hygiene-as-pipeline-invariant.
- **CivRealm ecosystem gotchas (verified in source):** PyPI 0.1.2 hard pins; image frozen 2024-04; startup health check fragile (issue #6: HTTP 502 → `port_utils.py` ValueError → wrap with retries, fail loudly); CivRealm deletes per-turn autosaves via the webapp's HTTP endpoints (`/listsavegames`, `/deletesavegame`) → our own checkpoint export path; `FreecivBaseEnv.reset(seed=)` sets mapseed/agentseed but leaves gameseed untouched; `randomly_generate_seeds: True` by default (must be overridden); `envs/__init__.py` imports `ParallelTensorEnv` unconditionally (PR #7 makes it optional). Verified source locators (review-round git-level check, 2026-10-24): `freeciv_base_env.py:171–191` (reset), `default_settings.yaml:99` (seeds), `civ_controller.py:664–703` + `:979–980` (autosave deletion, `requests.post` with no timeout), `client_state.py:192` (capstring) and `:229/:249/:255/:259` (settings), `build_server.py:47–54` (pulls `civrealm/freeciv-web`, retags `freeciv/freeciv-web`), `envs/__init__.py:1` (ray).

## 3. Architecture

- **Turn pipeline + numeric budgets:** snapshot ≤ 8,000 tokens, delta report ≤ 800, strategy memory ≤ 1,500 (current plan, falsifiable commitments with deadline turns, threat hypotheses) → one Mistral call (≤20 actions, ≤2 total API attempts per turn including repair) → validate each action against enumerated legal candidates (ownership, freshness, legality) → sequential execute with per-action read-back verification → finish phase → wait for next own phase. History: last turn full, older turns one-liners. **Overflow policy:** if a budget is exceeded, deterministic visibility-safe truncation applies (idle/distant units elided first, never armed-in-contact ones; candidate lists capped by priority) and the snapshot header discloses what was omitted; the truncation policy is validated on a large-empire fixture, not only opening turns. Mutations never re-sent without read-back proof of non-execution.
- **Batch semantics:** after each executed mutation the remaining batch actions are revalidated against refreshed state (a city founded mid-batch was not in the original candidate set); batch actions are grouped per acting entity (unit or city), and a stale or illegal action aborts the remaining actions of that entity's group only (logged as rejected) — other entities' actions proceed, the whole turn is never aborted; no third API attempt. **Finish phase has exactly one owner: the pipeline** (the model may request it; the pipeline sends `phase_done`).
- **Turn state machine + supervision:** `ACTING -> FINISH_SENT -> WAITING -> NEXT_OWN_PHASE | GAME_OVER | FAILED`. Per-operation deadlines: startup ≤ 120 s; per-mutation send+read-back ≤ 30 s; HTTP ≤ 15 s; teardown ≤ 30 s. **Per-state progress deadlines (activity-independent, enforced by the supervisor):** ACTING ≤ 180 s (the model phase); FINISH_SENT/WAITING ≤ pingtimeout-derived bound (720 s + margin); any state exceeding its deadline → FAILED/TRUNCATED with artifacts. **Run-level stall watchdog: no transcript event for 10 minutes → the ordered shutdown path.** Upstream blocking hazards are wrapped with hard deadlines and overrun is FAILED-with-artifacts: `CivController.close()` waits on a game-over message; save-deletion and score retrieval are synchronous HTTP without timeouts. **Process-level watchdog:** ordered shutdown → SIGTERM at deadline → SIGKILL. **Transcript durability:** the JSONL is append-only with one checksummed record per line, flushed (fsync) at the intent-before-write boundary and at each action boundary; on restart a trailing partial record is discarded; the WP3 kill test exercises mid-write, not merely between writes. **Outcome taxonomy:** COMPLETED (horizon) / DEFEATED / VICTORY / TRUNCATED (with reason) — infrastructure failure is separated from strategic loss in all reporting.
- **Uncertain mutations:** a mutation whose read-back is inconclusive after a disconnect is settled only by full-state reconciliation (target postconditions compared on reconnect); only verified non-execution permits resubmission; otherwise quarantined → bounded fail-stop with artifacts. Never blind replay.
- **Observation purity (pipeline invariant over the whole policy-facing surface):** observations, candidates, summaries, deltas, error messages, and memory are all visibility-gated. Unexplored / last-known / currently visible are distinguished; a vanished enemy is NOT destroyed; cold start after checkpoint load: revealed-but-not-visible mutable fields are unknown until observed. Fixture class: two worlds differing only in hidden mutable state must produce equivalent policy inputs. Privileged data (saves, scorelogs, admin output) never enters the policy pipeline; replay/evaluation views are separate. The illegal-action stream is fog telemetry (state-error share reported per run).
- **Action surface (v1):** units (adjacent move, found city, fortify/sentry, attack visible target, road/irrigation/mine where legal), cities (choose production), research (available tech), diplomacy (read status; decline/exit — first contact defaults to WAR in Freeciv, disclosed), finish phase. **Excluded, each with an explicit default:** exploration (broken upstream, decision 1), autosettler/auto-worker (`ActAutoSettler`/`SSA_AUTOWORKER` is made functional by PR #7 but is excluded — handing units to the server-side agent would silently erode model participation), naval, air, spies, caravans/trade routes, advanced treaty construction, citizen optimization, tax/luxury tuning (stretch), religion depth. README lists all exclusions and their defaults.
- **Provenance ledger (frozen in the transcript schema):** `model` / `continued_model_order` (linked to its origin) / `scripted_default` (with reason) / `engine_automatic` / `housekeeping`, at policy-choice level, with snapshot ID, offered candidates, choice, call ID, execution result, verification evidence. Participation gate: a turn has decision opportunities iff ≥1 consequential choice existed (research, production, unit action, diplomacy response); model participation = ≥1 executed `model`-class or model-originated `continued_model_order` decision on the turn; housekeeping, failed attempts, and zero-opportunity turns never enter numerator or denominator; the gate = model participation on ≥80% of turns-with-opportunities; PLUS per-domain model-control shares (research, production, expansion) majority-model across the run, with zero-choice domains reported n/a. Engine-automatic resolutions of new research/production choices are counted, never hidden. **Gate consequence:** if the participation gate fails, the run is still reported in full but labeled `degraded-dominant` and excluded from model-performance claims — gate failure never silently drops a run and does not by itself trigger cuts.
- **Honesty metrics — operational definitions frozen in the transcript schema; no metric ships without schema coverage:**
  - **Commitment follow-through:** commitments are structured objects the model emits (domain, target, deadline turn); a commitment is *fulfilled* by a ledger-verified matching executed action (same domain + registered target + compatible verb) within the deadline. Two shares are reported: *intent realized by any policy*, and *model-attributed* (fulfilling-action provenance ∈ {`model`, `continued_model_order` linked to that commitment}) — a scripted default realizing the promise is never credited as model follow-through. Denominator = commitments whose deadline falls inside the run; censored-at-horizon commitments excluded, not failed; duplicates de-duplicated per (target, domain).
  - **Reason-but-don't-act:** threat = an opponent/barbarian entity referenced in the model's structured output fields (entity IDs — no free-text parsing), de-duplicated per (entity, turn); acted = a ledger action targeting that entity, its tile or 8 neighbors, or a defensive response (fortify/garrison at the threatened settlement, or a move toward the threat tile) within ±2 turns; denominator = threat mentions whose window falls inside the run; censored at run boundaries. Reported as a share.
  - **Minimum-denominator rule:** any honesty-metric share with denominator < 5 is reported as "insufficient sample", not as a number.
  - **Illegal-action taxonomy:** schema-error / state-fog-error / illegal-in-rule; per-run shares over ALL model-emitted action attempts including repair outputs; repair prompts differ by class (state errors get state clarification; schema errors get bounded re-prompt).
- **Comparator vs degraded defaults (frozen domain/default table):** the **comparator** is the active scripted policy (settle-first, published deterministic research/production priority lists, minimal defense) used for paired evaluation; **degraded defaults** are the minimal end-of-turn fallback (preserve current orders, finish phase) used when the model is unresponsive after the repair cap; production/research needing a target with the model unavailable resolve via the same published priority lists, logged `scripted_default`. Separate entry points, both logged; every defaulted decision carries a reason.
- **Scenario-cut definition (the honest fallback deliverable, used instead of a post-WP0-gate base switch):** a PAIRED scenario segment — from an exported checkpoint, BOTH policies (model + comparator) run a matched ≥10-turn segment under the predeclared paired contract, with full metrics and replay artifacts — a paired mini-evaluation, not a solo demo. A distinct outcome covers infrastructure failure (e.g., checkpoint loading itself broken): TRUNCATED with artifacts and no performance claims.
- **Artifacts:** versioned append-only JSONL transcript → static HTML replay viewer (judges without the game verify method); exported start checkpoints checksummed; per-run manifest per decision 8.

## 4. Work packages

**WP0 — local provisioning + CivRealm spike (day 1, decisive).** Docker Engine is installed locally (29.7.2 — client verified; daemon version recorded at first successful connect). WP0 verifies daemon access for the session user (`docker info`; socket path checked first — snap installs use a different socket where the group fix does not apply; if denied: `sudo usermod -aG docker <user>` + re-login, scheduled to not kill active dev sessions; interim non-disruptive access for the spike via `sg docker -c` or documented sudo; the recipe contains no interactive prompts). Host arch check (amd64 — the digest pin is amd64-only). uv-managed Python 3.12 venv; pull the image by digest; **FIRST provisioning step: mirror bigai-ai/civrealm (dev @ `1b144d6`) and Baby1991/civgov-fixes (@ `36ae456`) into the repo's vendor/ — fork-deletion-proof before the gate**; apply the PR #7 fork branch; hardened startup (retries around the fragile pubstatus health check) with the image's published ports enumerated and checked for local collisions (webapp/proxy/server ranges), a clean-volume first start, and in-container save-path writability verified. Scripted, versioned provisioning recipe is an exit artifact. **Spike acceptance:** headless reset; scripted settle/move/set-research/set-production; 10 phase advances; **raw checkpoint export (copied only after save completion — stat, copy, re-stat, checksum-compare stability check) → server restart → load → identity verification (player attachment, turn number, clean adapter/memory init) + canonical state/config equality across arms (privileged comparison, outside the policy pipeline)** — the non-cuttable capability is proven on day 1 (WP3 hardens it); measured single-stack RSS/CPU; spectate smoke test including a zero-perturbation observer-attach check on a harness-driven game (an observer that cannot attach without taking a player slot or altering state → WP5 falls back to replay-viewer-only footage, decided day 1); capture-toolchain smoke (a 10 s clip recorded from the spectate source and encoded end-to-end); one-message rules check: **DONE (2026-10-24) — verified from the official text (`rules.md`, in-repo); no contradictions; the one amendment it forced (video ≤ 2 min, WP5) is applied.** **Per-patch classification at the gate, in writing:** each PR #7 item (incl. the AcceptTreaty commit) is applied / not-needed-for-our-surface / failed — a failed patch drops the affected verb from the action surface (via §3 exclusions) or triggers the switch, decided per verb. *Cut rule:* bounded fix attempts (one working day of effort); the base switch (decision 6) is permitted only at this gate; after the gate closes → scenario-cut. *Sub-budget:* provisioning (Docker, venv, image pull, vendoring, hardened startup) is capped at half of WP0; the spike gets the remainder.

**WP1 — Adapter + state extractor + scripted comparator (day 2).** Typed snapshot/delta schema, candidate enumeration per domain, fog fixtures (unexplored/last-known/visible; vanished-enemy case; the world-pair fixture; cold-start reload policy), the frozen domain/default table with **separate comparator and degraded-default entry points**; comparator completes 20 turns unattended. *Cut rule (ladder):* optional diplomacy reads and stretch actions cut first, then the action surface reduces to the pre-declared minimal floor (move, found city, research, production, finish); fog tests are never cut. The comparator is built BEFORE the model loop (it is the degraded-default engine and the ledger's `scripted` class).

**WP2 — Mistral agent loop + ledger (day 3).** Studio client (retry/backoff, per-call logging); **enforcement spike: `json_schema` vs schema-validated parsing, decision recorded in the manifest**; prompt templates as versioned files; memory module (pre/post-advance separation); provenance ledger; honesty metrics. **Acceptance:** every §3 metric's required inputs enumerated against the frozen transcript schema before freeze (schema-metric coverage check) **and each metric has a worked fixture (hand-computed expected value)**; 10 model-driven turns with read-back-verified effects; measured snapshot/delta/memory token counts over those turns within the §3 budgets **and the §3 truncation policy validated on a large-empire fixture**; degraded path exercised under fault injection (timeout, malformed output, invalid action); provenance + metrics report generated. *Feasibility decision at WP2 exit (cumulative):* measured mean per-turn wall-clock > 6 min → 1 evaluation pair; > 10 min → 1 pair AND the 25-turn horizon; **the ladder triggers are necessary, not sufficient — pairs/horizon are additionally computed from a wall-clock budget (measured arm runtime × turns × ≥1.5 contingency for retries and late-game turn growth must fit the recorded budget; at 6 min/turn, 2 pairs × 50 turns is ~10 h of model-arm time alone, which does not fit one idle day); evaluation may span the day boundary, and freeze applies to features, not run completion (decision recorded).**

**WP3 — Lifecycle + paired-run plumbing (day 4).** Identical exported start checkpoint launches both policies under a **predeclared paired contract** (equal observation format, candidate restrictions, action budgets, lifecycle handling for both; scenario/map parameters and checkpoint selection in the manifest; early-terminal reporting); our own copy-after-completion checkpoint export/preserve path (independent of CivRealm's autosave deletion); **disconnect-during-teardown acceptance (bounded FAILED, artifacts intact)**; **watchdog-kill test (append-only transcript survives SIGKILL)**; mid-mutation disconnect case (uncertain-mutation reconciliation); JSONL → static replay viewer. *Cut rule:* cut automatic crash recovery, never checkpoint reproducibility.

**WP4 — Evaluation + freeze (day 5).** Paired runs from identical checkpoints: target 2 pairs × 50 turns; cut ladder in order: second pair → horizon 50→25 → scenario-cut — the same-start same-horizon pair is never cut. **Sequential, idle-machine runs locally.** Metrics: score/turn curves (descriptive), cities/population/research progress, survival, invalid-action taxonomy, retries, tokens/cost/latency per turn, wall-clock per turn, all honesty metrics, provenance shares, **AI-state divergence-over-turns diagnostic per pair** (pair arms are not counterfactual-identical — README limitation). Crashes/stalls separated from strategic losses. Honest pilot framing — no model-ranking claims. Feature freeze at end of day 5 — **freeze applies to features, not run completion; evaluation runs may continue past the day boundary under the recorded wall-clock budget.**

**WP5 — Packaging (day 6).** README (prerequisites incl. local Docker topology, digest pin, provisioning recipe, OSS disclosure, licensing, exclusions + defaults, fog disclosure, scoped positioning), dev story from day-0 devlog, video (sources: local spectate footage + replay-viewer playback, smoke-tested day 1; **target 90–120 s, hard cap 2 min per rules.md:76**; 60–90 s fallback cut), no-secrets check, fresh-environment setup executed as written. Submission buffer.

## 6. Risks

- **CivRealm stack age** (frozen 2024, 3.3-dev server, protocol drift): mitigated by vendoring the PR #7 fork at pinned SHAs, digest pinning, per-patch gate classification, and the scenario-cut path. The 150-turn feasibility claim is single-source self-report — WP0 is its validation.
- **Python version:** host has 3.14, CivRealm pins predate it; uv-managed 3.12 is the validated path.
- **Fallback cost if exercised:** freeciv-mcp needs a from-source 3.2.6 build (2–4 h) plus a rewritten WP1 and has no long-game evidence — which is why the switch is gate-only and the scenario-cut is the preferred post-gate failure path.
- **AI-opponent nondeterminism:** classic-AI opponents are not proven deterministic given fixed seeds → evaluation instances pinned by exported checkpoints; the AI-divergence diagnostic quantifies pair-arm divergence; README states pair arms are not counterfactual-identical.
- **Local contention:** evaluation runs are sequential and measured with the machine otherwise idle (the same machine carries dev/video work); parallel only with measured zero contention.
- **Judging on "complexity" vs framework reuse:** addressed by scoped honest framing + the provenance/honesty contribution, not inflated claims.
- **Calendar:** 6 working days, deadline not treated as a constraint per user direction (rules verified from `rules.md`); WP0/WP1 gates protect the rest; the WP2-exit feasibility decision applies the evaluation cut ladder before resources are spent; video footage is smoke-tested on day 1, not day 6.
- **Residual unknowns by design:** P9 fork-default behaviors may force narrow-scenario disclosure; combat odds may not be exposed through CivRealm's client (a targeted check for `PACKET_UNIT_ACTIONS` action-probabilities is worth one probe before gating attacks without odds — otherwise attacks are candidate-gated without odds, disclosed).

**Adapter operational notes (source-verified, load-bearing):**
- `import civrealm` touches the network at import time: `port_utils` runs an HTTP pubstatus fetch at module import (port_utils.py:44–46), and `envs/__init__.py` imports ray on mainline (PR #7 makes it optional). Consequence: the runner imports `lechonk.adapter` lazily, only after the Docker stack is up; import failure is a startup failure, not a crash.
- `fc_args` is a process-global dict (configs/__init__.py:35–72). One env per process in v1; config set via `set_parameter` BEFORE `reset()`. Seeds: `reset(seed=)` sets only mapseed+agentseed (freeciv_base_env.py:188–191); **gameseed is sent only if `debug.gameseed` is present in fc_args** (client_state.py:118–132) — so the runner sets `randomly_generate_seeds=False`, `mapseed`, `gameseed`, `agentseed`, and **`self_play=False` (upstream default True silently renames the user `username1`, `username2`… on connection congestion, breaking the save-name prefix coupling below — congestion must raise loudly instead)** explicitly before reset.
- `reset()` blocks on server-up detection (retry budget ~120 s) then until the first turn is actionable; `step()` blocks on the action-probability queries. **Upstream timers that WILL truncate a slow run if left at defaults: `server_timeout: 30`, `begin_turn_timeout: 30` (armed at login and every end-turn — upstream's own comment warns to raise them for slow agents), `wait_for_timeout: 10000`; `Ports.get()` spins forever until an idle port exists.** The runner overrides all of these in fc_args to align with §3's supervision deadlines (ACTING ≤ 180 s → raise `server_timeout`; WAITING ≤ 720 s + margin → raise `begin_turn_timeout`), and the process supervisor bounds `Ports.get()` and the pubstatus retry loop.
- All upstream HTTP calls (`requests`) have no timeout — every one our adapter path can reach (`scorelog`, `listsavegames`, `deletesavegame`, `create_pbem_user` (in login, every reset), `gamesetting` (in game setup and load)) is wrapped at ≤15 s.
- Upstream side effects to contain: `logs/`, `recordings/`, `game_scores/` directories created in CWD (run from a dedicated working dir); `matplotlib` imported at module import.
- **Save/username coupling:** saves are named `{username}_T{turn}_{timestamp}`; `load_game()` validates the save's username prefix equals ours (civ_controller.py:707–723). Paired arms therefore run under the SAME pinned username as the checkpoint creator (sequential runs, so no connection conflict).
- **Checkpoint export (concrete primitive):** with Docker local, export = copy the save file out of the container/webapp save directory (`docker cp`) after CivRealm's begin-turn `/save` completes and before its end-turn HTTP deletion (civ_controller.py:944–947, 979–980, 664–705); stability check per §3; the exported file is the paired-run artifact (no HTTP download endpoint exists).
- Action tuples are `(ctrl_type, actor_id, action_key)`; `step(None)` ends the phase/turn; `'pass'` is a no-op. `get_info_and_observation()` is the read path, but not perfectly non-mutating: probability queries cancel unit activities first and restore them after (`cancel_orders_before_query_pro`/`restore_activity`) — a mid-read disconnect leaves activities cancelled, an uncertain-mutation window the runner's reconciliation handles (§3). **`build_city` is a two-round-trip action (name-suggestion wait, then the found-city packet) and gets a special-cased read-back; a mid-dance disconnect leaves founding ambiguous → reconciliation.**

### 7.2 Adapter interface inventory (what we consume)

- **Observation domains (TurnManager returns 11 keys; real content in `map, player, unit, city, dipl`, plus `game` (calendar, scenario, messages), `tech` (own player), `gov`; `rules/options/client` are placeholders):**
  - `map` (MapState, 8 arrays): `status` (0=unknown, 1=known-fogged, 2=seen — exactly our unexplored/last-known/visible trichotomy), `terrain`, `extras`, `output`, `tile_owner`, `city_owner`, `unit`, `unit_owner`. Terrain/extras written only when seen; owners only when seen (map_state.py:119–132).
  - `player`: per player `player_id, name, score, team, is_alive, nation, government, researching, research_name, tax/science/luxury`; own player adds gold, culture, bulbs_researched, researching_cost, techs_researched etc.; others add embassy-gated intel only (without embassy: only coarse hints leak — player_state.py:98–130). **Mainline `research_name` is broken (looked up in governments, player_state.py:73–74) — our snapshot computes research display from `tech` domain + ruleset tables until the PR #7 fix is verified applied.**
  - `unit`: per unit `owner, health, veteran, x, y, type_*` (attack/defense/firepower/move_rate/vision_radius_sq/worker...); own units add `home_city, moves_left, upkeep_*`; foreign units get −1 (unit_state.py:36–41). PR #7 adds `activity` + `ssa_controller`.
  - `city`: per city `id, owner, size, x, y, name`; own cities add production/shield/food stock, `can_build_unit`/`improvements` bitvectors, growth and turns-to-complete derivations; foreign cities get −1/zero (city_state.py:49–133).
  - `dipl`: per counterpart `diplomatic_state` (DS_*), active meeting clauses, meeting initializers — only states involving our player.
  - `tech` (own player): per tech `name, sup_units/improvements, is_researching, is_tech_goal, inv_state, reqs`.
- **Action surface we expose (post-patch verb set; all are CivRealm-registered actions with `is_action_valid` gating):**
  - units: `goto_<dir>` (8 dirs), `attack_<dir>`, `build_city`, `fortify`, `sentry` (ActSEntry — commented out on mainline; re-enabled by PR #7, verify at the per-patch gate), `build_road`, `irrigation`, `mine` (via ACTIVITY_ACTION_MAP verbs), `join_city`, `set_homecity`, `cancel_order` (as housekeeping), `keep_activity` (hold);
  - cities: `produce_<name>` (units and improvements), `city_buy_production`, `city_work_<i>_<dx>_<dy>` / `city_unwork_...`;
  - tech: `research_tech_<name>_<id>`, `set_tech_goal_<name>_<id>`;
  - diplomacy: `stop_negotiation_<p>`, `accept_treaty_<p>` (post-PR-7), `cancel_treaty_<p>`; `ignore_diplomacy_request` is unregistered upstream — its absence is a P9 probe item (decline path = stop_negotiation);
  - explicitly NOT exposed: chat, `set_sci_lux_tax`, `change_gov`, spy/trade/transport verbs, `produce_`-adjacent sell verbs, `ActAutoSettler`/`ActExplore` (§3 exclusions).
- **Combat odds:** upstream already issues per-unit-per-direction action-probability queries every turn (`packet_unit_get_actions`), and the probabilities arrive client-side in `unit_data[unit_id].action_prob[dir]` (reply pid 90), already gating action validity internally (civ_controller.py:415–417). The §6 residual is therefore only about surfacing them into our observation — likely straightforward; if it fails, attack candidates are gated without odds (disclosed).

### 7.3 Data schemas (drafts — frozen as pydantic models in WP1/WP2 with the coverage check)

- **Snapshot** (≤8,000 tokens rendered): `turn`, `player` (gold, tax rates, research: current target + progress + turns-left), `research_candidates[]` (name, cost, note — enumerated), `cities[]` (id, name, coords + relative direction/distance to capital, size, food/shield surplus, current production + turns-left, `production_candidates[]` top-N by priority list, buy_cost), `units[]` (id, type, pos, hp, moves_left, activity; per-unit `move_candidates` as relative directions with terrain notes; `attack_candidates` with odds if available), `map_view` (textual region summaries + named landmarks with relative directions — exact coordinates included, no inference required), `diplomacy[]` (counterpart, state, active meeting + clauses), `messages[]` (server events), `omitted` (truncation disclosure per §3).
- **Delta** (≤800 tokens): changed/lost units, city growth/production completion, research progress/completion, new contacts/meetings, combat events, warnings.
- **ActionBatch** (model output, ≤20): `{ turn_id, actions: [{ ref: <candidate_id>, }...], commitments: [{ domain, target, deadline_turn }...], finish_requested: bool, notes }` — **actions reference candidate IDs only; raw coordinates from the model are rejected as schema-error** (the batch schema defines `ref` as a candidate ID — a coordinate is a schema violation; the repair prompt re-attaches the full candidate table).
- **TranscriptRecord** (append-only JSONL, one union type per line, each with `seq, ts, checksum`): `run_manifest` (decision 8 fields) / `turn_start` / `snapshot_ref` (hash + token count) / `candidates_ref` (hash + count of the offered candidate table — the §3 ledger's offered-candidates requirement, rendered by the viewer) / `model_call` (prompt hash, latency, tokens, cost, fingerprint) / `action_result` (ref, outcome: executed|rejected{class}|aborted-group, read-back evidence, provenance class) / `commitment` / `metric_event` / `outcome` (COMPLETED/DEFEATED/VICTORY/TRUNCATED + reason).

### 7.4 Comparator and degraded-default tables (draft contents — published verbatim in the README)

- **Research priority list** (first affordable legal candidate wins): Alphabet → Pottery → Agriculture (irrigation prerequisite chain) → Bronze Working → Writing → Currency → Masonry → Wheel → trade-adjacent techs; tie-break: lowest cost, then list order.
- **Production priority list** (per city, first legal): defensive unit if city undefended → builder-type unit while improvements remain and builders < cities+1 → growth building (Granary-class) → science building → wealth fallback. Buy-production when gold > 2× buy_cost and shield stock < 25% complete.
- **AMENDMENT (2026-10-24, user-approved) — production hysteresis; this amends the frozen production priority list above.** Live evidence (`artifacts/runs/wp1-comparator/`, seed 20261026, 20-turn unattended run): upstream `available_actions` never lists a city's CURRENT production target as a produce candidate, so the frozen ladder alternated Warriors → Barracks → Warriors every turn (city 111, turns 2–20, `defensive_unit_undefended_city` / `fallback_production` each turn) and nothing completed — the comparator was faithful to the frozen wording; the wording was missing the current-target case. **Rule:** a production tier is SATISFIED if the city's current production target already belongs to that tier's output class, even when the target is absent from the candidate table; a satisfied top applicable tier does not switch. Hysteresis never suppresses a legitimate higher-priority switch: a current target satisfying only a lower tier does not protect it (an undefended city producing Barracks still switches to the defensive unit; a defended city producing a growth building still switches to a builder unit while the builder tier applies). **Rationale:** tier-class satisfaction — not exact-item equality against the candidate table — is what the ladder's intent ("defensive unit if city undefended") already means; the candidate-table omission is an upstream enumeration artifact, not a policy signal. The degraded-defaults entry point is unaffected (it preserves production anyway and only resolves EMPTY production, where no target exists to satisfy a tier). Implemented in `src/lechonk/comparator/scripted.py` (`production_pick`); re-verified live under `artifacts/runs/wp1-comparator-amended/`.
- **Unit defaults:** found city on the first legal candidate tile when a settler exists and no city is being founded this turn; else improve (road/irrigation/mine by terrain yield); else fortify. Military: defend the nearest own city; attack only adjacent visible targets with favorable odds (or without odds data if the probe fails, per §6).
- **Diplomacy default:** decline/stop all negotiations; no proactive offers.
- **Degraded-defaults entry point** (distinct from comparator): preserve all current orders and production, finish phase; only NEW mandatory choices (research completed, city production empty) resolve via the priority lists, logged `scripted_default`.

### 7.5 Prompt template outlines (versioned files; hashes in the manifest)

- **system prompt**: role, rules of the interface (candidate IDs only, budgets, commitment grammar), fog disclaimer ("vanished ≠ destroyed; unknowns are real"), action-surface cheat sheet.
- **strategy/tactical prompt** (one call per turn): [stable prefix: rules + cheat sheet] + memory (≤1,500) + snapshot (≤8,000) + delta (≤800) + candidate table summary → output: ActionBatch (json_schema or validated-parse per WP2 decision). Stable prefix enables prompt caching (chonk-doom lesson).
- **repair prompt (attempt 2, per error class)**: schema-error → "re-emit conforming to the schema; actions must be candidate IDs"; state-fog-error → "the state changed; here are the refreshed candidates for the failed refs; re-emit"; illegal-in-rule → "this candidate became illegal; refreshed list attached".
- **memory update** is NOT a separate API call: the per-turn ActionBatch output carries a `memory_update` section (plan/commitment/threat updates within the ≤1,500-token budget; falsifiable phrasing required) — one request per turn total (decision 4); on a repair attempt the last valid memory persists.

### 7.6 Replay viewer (static, no server)

Single self-contained HTML + JS loading a JSONL transcript (bundled per run): per-turn timeline (score curve, cities, units, gold), snapshot summary panel, model batch with provenance chips (model/scripted-default/engine-automatic/housekeeping, color-coded), commitments board (open/fulfilled/missed with deadline turns), metrics timeline (participation, follow-through, reason-but-don't-act, illegal-action shares), and the run manifest. Published artifacts let judges without the game verify method (decision 5b).

### 7.7 Metrics computation (formulas over the ledger; definitions and censoring per §3)

- participation = count(turns_with_model_participation) / count(turns_with_opportunities); per-domain shares analogous over domain-choice events, n/a when zero choices.
- commitment follow-through: for each commitment c with deadline inside the run: fulfilled_any(c) = ∃ ledger action a: match(a, c) ∧ turn(a) ≤ deadline; fulfilled_model(c) = fulfilled_any ∧ provenance(a) ∈ {model, continued_model_order(c)}; report both shares.
- reason-but-don't-act: for each (entity, turn) mention m with window inside the run: acted(m) = ∃ ledger action targeting entity, its tile or 8 neighbors, or defensive response within ±2 turns; share = 1 − acted-rate.
- illegal-action shares = counts by class / all model-emitted attempts (incl. repair outputs).
- AI-state divergence per pair: per-turn distance between arms over (score, city count, units, known tiles) — descriptive curve only.
- Minimum-denominator rule (<5 → "insufficient sample") applies to every share; all formulas validated by the WP2 worked fixtures.
